# MetaMath 多選題練習頁需求規格（補完版）

## 1. 專案定位

本專案為一個手機優先的單頁式數學多選題練習頁，目標是讓使用者在手機螢幕上完成以下流程：

1. 讀取題目
2. 勾選所有正確選項
3. 送出答案
4. 在檢討頁查看逐題判定與建議

本頁面以純前端實作為主，題目資源以 `data.json` 形式外部載入，使用者可透過修改題庫內容來切換題目。

---

## 2. 需求分析與現況補強

原先的需求規格已經涵蓋了主要方向，但仍有幾個關鍵細節需要補齊，否則工程實作容易出現歧義：

- 題庫資料格式必須明確定義，不能只說有題目、選項、回饋
- 評分規則應明確界定「幾個對幾個錯」如何計分，而非只說取消評分規則
- 檢討頁應該明確列出每個選項的狀態，不只是預設批改內容
- 自訂元件 `frame-panel` 必須定義其 HTML 結構、屬性、樣式責任與動畫能力
- `MathShow` 的數學排版需求應納入非功能需求與可維護性需求

本補完版會把上述缺口一併補足。

---

## 3. 使用者故事

### 3.1 使用者故事

- 作為使用者，我希望在手機上快速閱讀題目與多個選項。
- 作為使用者，我希望能夠多選並且送出答案。
- 作為使用者，我希望送出後能立即看到每個選項是否正確、哪裡漏選或誤選。
- 作為使用者，我希望不必重複手動刻畫框線與標題，頁面元件一致可維護。

### 3.2 系統目標

- 支援單題題目資料載入
- 支援多選作答與即時判定
- 支援檢討頁逐項回饋
- 支援題庫切換
- 支援小型手機螢幕閱讀

---

## 4. 頁面流程

### 4.1 主流程

1. 首頁載入時呼叫 `fetch('./data.json')`
2. 若載入成功，渲染題目、提示、選項與 meta 標籤
3. 使用者勾選選項
4. 點擊「送出答案」
5. 若未選擇答案：顯示錯誤提示並保留在作答頁
6. 若已選擇答案：依資料判定結果，顯示檢討頁
7. 檢討頁列出每個選項的判斷與對應回饋

### 4.2 分頁切換

- 頂部有兩個切換按鈕：作答、檢討
- 亦可透過左右滑動切換頁面
- 切換頁面時需同步更新按鈕 active 狀態

### 4.3 錯誤處理

- `data.json` 讀取失敗時，不得直接白屏
- 顯示明確錯誤訊息：請確認題庫是否存在或格式是否正確
- `submit` 於未作答時，不得進入檢討頁

---

## 5. 功能需求

### 5.1 題庫載入

- 頁面載入時自 `data.json` 讀取題庫資料
- 必須支援 JSON 格式驗證
- 若讀取失敗，顯示錯誤訊息並停用送出功能
- 題庫成功載入後才允許作答

### 5.2 題目顯示

- 顯示題目標題
- 顯示多個 meta 標籤
- 題目與選項支援數學公式渲染
- 題目與選項的內容都應允許含有 `\(` `\)`、`\[` `\]` 等數學格式

### 5.3 選項互動

- 每個選項使用 `checkbox`
- 允許多選
- 每個選項至少需顯示以下資訊：
  - 選項代號（如 A、B、C、D）
  - 選項文字
- 使用者選擇答案後，送出前可再次修改

### 5.4 送出判定

- 使用者未勾選任何答案時，送出會觸發明顯錯誤狀態
- 當至少勾選一個答案時，系統依 `correctAnswers` 與使用者選擇進行判定
- 判定完成後，自動切換到檢討頁

### 5.5 檢討頁需求

檢討頁應顯示：

- 每個選項是否正確
- 每個選項是否勾選
- 兩個資訊需分開呈現，不合併為單一 4 種狀態
- 對應的預設回饋文字

## 6. 資料格式需求

### 6.1 `data.json` 結構

題庫資料格式以簡單的結構為主，至少包含以下內容：

```json
{
  "title": "題目文字",
  "meta": ["標籤1", "標籤2"],
  "options": [
    {
      "id": "A",
      "text": "選項內容",
      "correct": true
    },
    {
      "id": "B",
      "text": "選項內容",
      "correct": true
    },
    {
      "id": "C",
      "text": "選項內容",
      "correct": false
    },
    {
      "id": "D",
      "text": "選項內容",
      "correct": false
    },
    {
      "id": "E",
      "text": "選項內容",
      "correct": false
    }
  ],
  "grading": {
    "A": "批改內容 A",
    "B": "批改內容 B",
    "AB": "批改內容 AB"
  }
}
```

### 6.2 欄位說明

- `title`：題目主文，支援 LaTeX 或數學格式
- `meta`：題目標籤，例如代數、幾何、根式、多選
- `options`：所有選項陣列
  - `id`：選項代號，如 A/B/C/D/E
  - `text`：選項內容
  - `correct`：是否為正解
- `grading`：批改對照表
  - 以使用者勾選的選項組合為 key，例如 `A`、`B`、`AB`
  - 對應值為預設批改內容
  - 預設選項數為 5 項
  - 對應預設批改內容為 32 項

### 6.3 資料驗證需求

- `options` 必須存在且至少有1個選項
- `grading.correctAnswers` 必須與 `options` 的 `id` 對應
- 題目內容不允許缺失 `title` 與 `options`
- 題庫載入時理應驗證格式完整性，避免跑出錯誤結果

## 7. UI/UX 設計需求

### 7.1 全域介面

- 以手機尺寸優先設計
- 從螢幕寬度與內容可讀性角度考量，使用單欄佈局
- 主畫面不可整體捲動，但各頁內部區塊允許垂直捲動
- 左右滑動可切換作答頁與檢討頁

### 7.2 頂部導覽

- 顯示品牌名稱 `MetaMath`
- 顯示兩個切換按鈕：作答、檢討
- 當前頁面高亮顯示

### 7.3 作答頁內容區塊

作答頁至少包含三個區塊：

1. 題目區
2. 選項區
3. 送出按鈕

### 7.4 檢討頁內容區塊

檢討頁至少包含：

1. 本題能力分析
2. 各選項逐項判定
3. 預設建議文字

### 7.5 狀態回饋

- 未勾選直接送出時，選項區應有明顯抖動動畫或錯誤提示
- 檢討頁應讓使用者快速看出：
  - 正確選項
  - 誤選選項
  - 漏選選項

---

## 8. 自訂元件需求

### 8.1 `frame-panel`

`frame-panel` 為通用框線標題容器元件，責任如下：

- 以 `title` 屬性設定標題文字
- 可選擇 `subtitle` 提供補充說明
- 元件內部自行繪製框線
- 標題需跨在框線外側顯示
- 標題背景需與內容底色一致
- 提供 `shake` 動畫能力
- 元件應使用 `div` 包裝內容區塊，避免外部樣式破壞框線與標題顯示

### 8.2 共用元件使用方式

- 題目區、選項區、檢討區應全部使用同一個 `frame-panel` 元件
- 外層頁面只負責插入內容，不重寫框線與標題邏輯

### 8.3 元件行為需求

- 需要支援 `class` 傳入與外部樣式覆寫
- 需要支援內容區塊自動捲動
- 元件可被外部以 `classList.add('shake')` 觸發抖動動畫

---

## 9. 數學渲染需求

### 9.1 `MathShow`

數學題目內容需支援動態渲染，核心要求如下：

- 透過自訂元素 `<math-show>` 包裝內容
- 當元素內容變更時，自動重新排版
- 需載入 MathJax 3 的 `tex-svg.js`
- 若 MathJax 尚未完成載入，需延後套用渲染
- 若渲染失敗，至少不應影響整體頁面運作

### 9.2 渲染原則

- 題目與選項內容均接受 LaTeX 字串
- 元素可支援 `inline` 屬性以便於行內顯示
- 不應讓數學公式破壞 UI 排版

---

## 10. 非功能需求

### 10.1 可維護性

- 題目邏輯與 UI 結構分離
- 資料內容與前端程式分離
- 避免把題目內容直接硬編碼進 `index.html`

### 10.2 可讀性

- 使用者能在小尺寸手機中閱讀題目與選項
- 避免過長文字導致版面崩潰

### 10.3 可擴充性

- 未來可擴充多題循環題庫
- 未來可支援不同題型與不同不同評分模型
- 未來可加入多個能力點分析或個人進度紀錄

---

## 11. 驗收準則

以下條件滿足時，視為本需求完成：

1. 頁面可成功從 `data.json` 載入題目資料
2. 題目與選項能正確顯示數學公式
3. 用戶可以藉由 checkbox 多選答案
4. 未作答直接送出時會顯示明確提示
5. 送出後可自動切換到檢討頁
6. 檢討頁能逐項顯示對錯與回饋
7. 版面於手機尺寸下可正常閱讀
8. `frame-panel` 可共用於各區塊且外層頁面不重複張貼框線邏輯

## 12. 建議的後續工程事項

### 12.1 目前可立即補強

- 補齊 `frame-panel.js` 自訂元件實作
- 補齊 `data.json` 結構驗證器與錯誤訊息
- 於作答頁加入「請先勾選答案」的可視提示狀態
- 於檢討頁追加「正確答案數量 / 選項詳細判定」的統計

### 12.2 未來可擴展方向

- 支援題目列表與題庫切換
- 支援分數紀錄與答題歷程
- 支援多題連續挑戰模式
- 支援錯題重做與個人化練習路徑

---

## 13. 結論

本專案的核心價值，不只是「能做出一個多選題頁面」，而是要建立一個可持續開發、可切換題庫、可支援數學公式渲染、可提供明確作答與檢討回饋的手機練習系統。

目前原始規格已具備基本方向，但若要成為可交付的工程需求，本補完版應可作為主要參考文件。
