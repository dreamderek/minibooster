# 五選多選題生成與回饋規則

## 題目 JSON 文件格式

每一題必須存成一個可解析的 UTF-8 JSON 檔，且根物件只能包含 `title`、`meta`、`options`、`grading` 四個欄位，格式如下：

```json
{
  "title": "題目敘述。數學式使用 \\(\\displaystyle x^2\\)。",
  "meta": ["單元名稱", "可選的次分類"],
  "options": [
    {
      "id": "A",
      "text": "選項敘述",
      "note": "此選項正確或錯誤的計算、公式或反例。",
      "correct": true
    },
    {
      "id": "B",
      "text": "選項敘述",
      "note": "此選項正確或錯誤的計算、公式或反例。",
      "correct": false
    },
    { "id": "C", "text": "選項敘述", "note": "解析", "correct": true },
    { "id": "D", "text": "選項敘述", "note": "解析", "correct": false },
    { "id": "E", "text": "選項敘述", "note": "解析", "correct": true }
  ],
  "grading": {
    "A": "選 A 時的回饋",
    "B": "選 B 時的回饋",
    "C": "選 C 時的回饋",
    "D": "選 D 時的回饋",
    "E": "選 E 時的回饋",
    "AB": "選 A、B 時的回饋",
    "AC": "選 A、C 時的回饋",
    "AD": "選 A、D 時的回饋",
    "AE": "選 A、E 時的回饋",
    "BC": "選 B、C 時的回饋",
    "BD": "選 B、D 時的回饋",
    "BE": "選 B、E 時的回饋",
    "CD": "選 C、D 時的回饋",
    "CE": "選 C、E 時的回饋",
    "DE": "選 D、E 時的回饋",
    "ABC": "選 A、B、C 時的回饋",
    "ABD": "選 A、B、D 時的回饋",
    "ABE": "選 A、B、E 時的回饋",
    "ACD": "選 A、C、D 時的回饋",
    "ACE": "選 A、C、E 時的回饋",
    "ADE": "選 A、D、E 時的回饋",
    "BCD": "選 B、C、D 時的回饋",
    "BCE": "選 B、C、E 時的回饋",
    "BDE": "選 B、D、E 時的回饋",
    "CDE": "選 C、D、E 時的回饋",
    "ABCD": "選 A、B、C、D 時的回饋",
    "ABCE": "選 A、B、C、E 時的回饋",
    "ABDE": "選 A、B、D、E 時的回饋",
    "ACDE": "選 A、C、D、E 時的回饋",
    "BCDE": "選 B、C、D、E 時的回饋",
    "ABCDE": "全選時的回饋"
  }
}
```

### 欄位定義

- `title`：必填字串。題幹須清楚說明題意與作答要求，不得包含答案或正解提示。
- `meta`：必填的非空字串陣列，只能放本題實際考查的「知識點」；同一題內不可有重複標籤。不得使用學制、年級、科目或章節範圍作為標籤，例如「高一數學」、「高中數學」、「代數」皆不可使用。可使用具體知識點，例如「等比數列」、「等比級數」、「弧度量」、「扇形面積」、「平方差公式」。
- `options`：必填陣列，且只能有 5 個物件，順序與 `id` 必須固定為 A、B、C、D、E。每個物件只能包含下列欄位：
  - `id`：必填字串，為對應的 A、B、C、D 或 E。
  - `text`：必填非空字串，為顯示給學生的選項內容。
  - `note`：必填非空字串，說明該選項正確或錯誤的理由。
  - `correct`：必填布林值；`true` 代表正確選項，`false` 代表錯誤選項。不可使用字串 `"true"` 或 `"false"`。
- `grading`：必填物件。key 為學生實際勾選的選項組合，value 為對應的非空回饋字串；不得加入未作答的空字串 key。

### JSON 內的 LaTex 跳脫規則

- `title`、`options[].text`、`options[].note` 與 `grading` 的回饋文字只要包含 LaTex，都必須使用行內分隔符 `\\(` 與 `\\)`。
- 為避免分數、根號、上下標等數學式的字體大小不一致，每一個行內 LaTex 式都必須在開頭加入 `\\displaystyle`。例如 JSON 原始檔應寫成 `\\(\\displaystyle \\frac{1}{2}\\)`，不可只寫 `\\(\\frac{1}{2}\\)`。
- JSON 字串中的反斜線是跳脫字元，因此**原始 `.json` 檔內每一個 LaTex 反斜線都必須寫成兩個反斜線 `\\`**。JSON 解析後才會還原成前端渲染器需要的一個反斜線 `\`。
- 正確範例（直接寫入 `.json` 檔）：

  ```json
  {
    "title": "解方程式 \\(\\displaystyle x^2=4\\)。",
    "text": "\\(\\displaystyle \\frac{1}{2}\\times 60^\\circ=30^\\circ\\)",
    "note": "由 \\(\\displaystyle a_4=2r^3\\) 求 \\(\\displaystyle r\\)。"
  }
  ```

- 錯誤範例：`"\(\displaystyle x^2=4\)"`。這在 JSON 原始檔中使用單反斜線，會造成 JSON 跳脫錯誤或使 LaTex 指令被破壞。
- 不可過度跳脫為 `"\\\\\\\\(\\\\\\\\displaystyle x^2=4\\\\\\\\)"`；解析後會留下兩個反斜線，前端無法辨識為 LaTex 分隔符。
- 常見指令同樣適用：`\\frac`、`\\times`、`\\circ`、`\\pi`、`\\theta`、`\\displaystyle`、`\\langle`、`\\cdots` 都必須以雙反斜線儲存。例如角度應寫為 `\\(\\displaystyle 180^\\circ\\)`，而不是 `180 度`。

`grading` 必須且只能包含以下 31 個 key：

```text
A, B, C, D, E,
AB, AC, AD, AE, BC, BD, BE, CD, CE, DE,
ABC, ABD, ABE, ACD, ACE, ADE, BCD, BCE, BDE, CDE,
ABCD, ABCE, ABDE, ACDE, BCDE,
ABCDE
```

## 題目結構

- 題目為一到高中數學範圍的 5 選項多選題，選項固定為 A、B、C、D、E。
- 每個選項都要對應至少一個可檢核的知識點；不同選項可考相同知識點，也可一個選項考多個知識點。
- 每個選項必須提供 id、text、correct 與 note；note 要以計算、公式或反例說明該選項為何正確或錯誤。
- 題幹、選項、note 與 grading 回饋中的數學式一律使用行內 LaTex 語法 `\\(\\displaystyle ...\\)`；下標、上標等結構不可省略，例如 `\\(\\displaystyle a_4=2r^3\\)`，以確保方程式可讀且字體大小一致。

## 避免可猜的答案規律

- 不得讓連續題目出現相同的正解組合。
- 不得讓連續題目固定為前幾個選項正確、最後一個選項錯誤，例如連續出現 ABCD。
- 正確選項數量應在題庫中分散；一般可使用 2 至 4 個正確選項，並避免連續多題有相同數量。
- 正確選項的位置必須分散。錯誤選項不可總是集中在最後一項，也不可固定集中在相鄰位置。
- 出題完成後，應檢查最近的題目檔，確認正解組合、正確選項數量與錯誤選項位置均未形成可預測模式。

## 作答組合回饋

- 必須為 31 種「至少選一項」的作答結果預先建立回饋；未作答不建立 grading 項目，由前端顯示預設提示。
- 作答組合的 key 必須由選取的選項代號依 A 至 E 排序串接，例如 AC、BDE、ABCDE。
- 每一組回饋都必須口語化、具體且與該題選項一致。回饋角色是老師根據學生「勾選結果」推測其理解狀態；因沒有學生的實際計算過程，不得把勾選結果當成能力已被證明的事實。
- 對正確有選、錯誤沒選的選項，使用保留與推測語氣描述可能具備的觀念。例如「看來你能夠用……判斷」、「這可能表示你有注意到……」或「你似乎有避開……的陷阱」。不得使用「答得好」、「算得精準」、「你已掌握」、「你很熟悉」、「全對」等肯定、稱讚或評定能力的用語。
- 對正確沒選、錯誤有選的選項，以常見迷思推測可能的誤解，再給出可操作的修正建議。例如「大部分人常常錯在……」、「也許你是把……當成……」或「可以先用……檢查」。不得直接斷言學生「不會」、「沒掌握」或「觀念錯誤」。
- 每組回饋至少須包含一項依勾選結果的推測，以及其他選項的判斷或修正建議；不可只寫「正確選項為……」。
- 回饋若超過兩句、包含兩個以上的判斷重點，或文字較長時，必須依語意以 `<br>` 分段換行，避免整段輸出影響閱讀。建議分為「可能理解的觀念」與「待檢查／下一步」兩段。
- `<br>` 必須直接存入 JSON 字串；不要只使用實際換行或 `\n`，因為前端顯示時可能被合併為同一段文字。例如：`"看來你能夠使用等比數列的通項。<br>再用 \\(\\displaystyle a_4=2r^3\\) 檢查公比。"`。
- 回饋文字（不含 LaTex 公式內）每遇到斷句如:句號 `。` 分號 `；` 問號`?` 驚嘆號`!` 等時，都必須立即加入 `<br>` 換行；最後一句結尾可省略 `<br>`。例如：`"看來你能夠使用等比數列的通項。<br>也許公比還需要再檢查；<br>可代入 \\(\\displaystyle a_4=2r^3\\) 驗算。"`。
- 回饋內文使用函數時要使用latex語法，優化可讀性。

### 過長 LaTex 公式的斷行規則

- 不得把過長的推導、連續等式或多個條件放在同一個行內 LaTex 式中。公式可能超出面板寬度時，必須主動分段，而不是依賴前端自動折行。
- 優先使用 `<br>` 在語意完整處拆成文字與短公式。例如直接存入 JSON 的寫法：`"先列出條件：<br>\\(\\displaystyle a_4=a_1r^3\\)<br>代入數值得：<br>\\(\\displaystyle 16=2r^3\\)"`。
- 同一組必須對齊的多步推導，使用 `aligned` 環境並以 LaTex 的 `\\` 換行；JSON 原始檔中的該換行指令必須寫成四個反斜線 `\\\\`。例如：

  ```json
  {
    "note": "\\(\\displaystyle \\begin{aligned} a_4&=a_1r^3\\\\ 16&=2r^3\\\\ r&=2 \\end{aligned}\\)"
  }
  ```

- 每一行只放一個主要運算步驟；條件、代入、結論應分行。不要以大量空白、實際換行或 `\n` 強迫公式排版。

## 交付前檢查

- JSON 必須可解析，且有 5 個選項。
- grading 必須剛好有 31 組非空白回饋，並覆蓋所有至少選一項的組合；不可包含未作答的空字串鍵。
- 選項的 correct 狀態、note 與每一組 grading 回饋必須互相一致。
- 新題目直接加入 `data/questions` 資料夾；檔名使用 `q001.json` 至 `q999.json` 的編號格式。`q000.json` 是空白範本，不會出題。新增、刪除或重新命名題檔後，在專案根目錄執行 `node tools/generate-question-index.js` 重建 `data/questions/index.json`。工具只會收錄有效的 `qNNN.json` 檔案，且會先驗證每個題檔皆可解析為 JSON。
